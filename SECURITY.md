# Security Policy

## Reporting a vulnerability

Do **not** report suspected vulnerabilities in public GitHub issues, discussions, pull requests, screenshots, or commits.

Use this repository's GitHub private vulnerability-reporting flow:

1. Open the repository's **Security** tab.
2. Choose **Advisories** and then **Report a vulnerability**.
3. Include the affected commit or version, a minimal reproduction using synthetic data, impact, and any suggested mitigation.

Do not attach credentials, private keys, customer media, production logs, card serial numbers, NAS addresses, or other personal or operational data.

## Maintainer prerequisite

Before the repository is made public, a maintainer must enable GitHub private vulnerability reporting in repository settings. Until that is enabled, public issue reporting is not an acceptable channel for security-sensitive details.

## Response scope

This is a pre-release project. Reports are reviewed on a best-effort basis; no response-time or supported-version commitment is made by this document. A valid report may be acknowledged, investigated, mitigated, or deferred according to impact and available release evidence.
